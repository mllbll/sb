# Модель детекции

## Как работает пайплайн

Точка входа — `model/detection.py`. При запуске создаётся один `CameraWorker` на каждый источник из `sources` в `secrets.json`. Все воркеры стартуют параллельно.

Каждый воркер запускает 4 потока:

**reader** — читает RTSP-поток через OpenCV + FFmpeg. Держит только последний кадр в очереди размером 1. Если камера отваливается, пробует переподключиться через `reconnect_sleep_sec`.

**inference** — забирает кадры из очереди, прогоняет через YOLO, фильтрует по ROI, находит скопления. Результаты кладёт в `_cached_*` поля под локом.

**main-loop** — рисует оверлей, сохраняет preview и event-кадры, раз в `write_interval_sec` пишет статистику в БД.

**db-writer** — неблокирующая очередь для записей в PostgreSQL. Main-loop только кладёт задачи, db-writer их разгребает асинхронно.

YOLO-модель загружается один раз и шарится между всеми воркерами. Вызовы `model()` сериализуются через `_model_lock`, чтобы не было гонок на уровне PyTorch.

## Алгоритм поиска скоплений

Реализован в `model/utils.py`, функция `find_crowd`.

Принцип: обход связных компонент через DFS. Два человека попадают в одну компоненту, если выполняется хотя бы одно условие:

1. IoU их bbox'ов больше `crowd_iou_threshold` (дефолт 0.0, то есть физическое перекрытие)
2. Расстояние между центрами меньше порога

Порог расстояния считается в зависимости от `crowd_overlap_mode`:

**adaptive** (дефолт) — `CROWD_ADAPTIVE_DIST_MULT * max(diagonal_box1, diagonal_box2)`. Порог адаптируется под размер людей в кадре. Хорошо работает, когда камера смотрит под углом и люди разного размера в разных частях кадра.

**fixed** — фиксированное количество пикселей (`crowd_center_dist_px`).

Скоплением считается компонента из `crowd_min_people` и более человек (дефолт 5).

Если включён `crowd_debug_components`, в stdout печатаются размеры всех найденных компонент — удобно для подбора параметров.

## ROI (Region of Interest)

Детекция считает только людей, чьи bbox'ы попадают в ROI. Это позволяет исключить людей за стеклом, в соседних помещениях и т.д.

Два способа задать ROI в `secrets.json`:

**Пиксельный** (`roi_box`) — координаты `[x1, y1, x2, y2]` в пикселях для разрешения `roi_base_w × roi_base_h`. Если камера отдаёт другое разрешение, ROI масштабируется автоматически.

**Дробный** (`roi_frac`) — доли от размера кадра, например `{"x1": 0.1, "y1": 0.1, "x2": 0.9, "y2": 0.9}`. Имеет приоритет над `roi_box`. Не зависит от разрешения камеры.

Режим фильтрации задаётся через `crowd_roi_mode`:

| Режим | Условие |
|-------|---------|
| `center` (дефолт) | центр bbox'а внутри ROI |
| `intersect` | bbox хоть как-то пересекается с ROI |
| `inside` | bbox целиком внутри ROI |

## Запись в БД

Запись происходит в двух случаях:

- Каждые `write_interval_sec` секунд (дефолт 30) — текущий счётчик людей и количество скоплений
- При каждом новом скоплении (с дебаунсом `crowd_timeout_sec`) — дополнительно сохраняется кадр в `output_dir` и путь к нему пишется в поле `filename`

## Параметры настройки

Все параметры — в `keys/secrets.json`. Наиболее полезные для тюнинга:

| Параметр | Дефолт | Описание |
|----------|--------|----------|
| `yolo_conf` | 0.35 | Минимальная уверенность YOLO. Снизить если пропускает людей, поднять если много false positive. |
| `crowd_min_people` | 5 | Минимум людей для признания скоплением |
| `crowd_overlap_mode` | adaptive | Как считать близость между людьми |
| `crowd_adaptive_dist_mult` | 1.2 | Множитель в adaptive-режиме. Поднять, если скопления не склеиваются. |
| `crowd_center_dist_fraction` | 0.06 | Базовый порог расстояния как доля от диагонали ROI |
| `write_interval_sec` | 30 | Как часто писать периодическую статистику |
| `crowd_timeout_sec` | 2 | Дебаунс между event-записями при одном длинном скоплении |

## Добавить новую камеру

1. Добавить источник в `sources` в `secrets.json`:
   ```json
   {"id": "new_cam", "rtsp_url": "rtsp://..."}
   ```
2. Добавить зону в `zones`:
   ```json
   {"id": "z3", "camera_id": "new_cam", "name": "Название", "max_capacity": 100}
   ```
3. Перезапустить контейнер `model`.

Никаких изменений в коде не нужно — пайплайн читает `SOURCES` и создаёт по воркеру на каждый источник.
